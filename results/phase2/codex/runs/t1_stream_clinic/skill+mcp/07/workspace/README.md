# Live clinic intake transcription

Run from this directory with the API key exported in your shell:

```bash
./run.sh sample.wav out.json
```

Input must be 16 kHz, mono, signed 16-bit PCM WAV. The runner strips the
WAV header and sends 50 ms binary audio chunks at real-time speed to AssemblyAI
Streaming v3. The final short chunk is padded with silence.

It uses `universal-3-6-pro`, Medical Mode (`medical-v1`), speaker diarization,
and server-side PII redaction with all supported policies. Partial turns are
explicitly disabled because AssemblyAI only redacts final turns. Transcripts
therefore arrive at turn completion rather than word by word. Before sending
audio, the runner requires the server's `Begin.configuration` to confirm the
model, Medical Mode, speaker labels, and redaction.

Outputs:

- `out.json`: `{"turns": [{"speaker": "A", "text": "..."}]}` with one entry per
  final API turn, ordered by `turn_order`. Speaker revisions are applied in
  arrival order, including those sent at session termination. Consecutive turns
  may have the same speaker. Unresolved labels remain `PENDING` or `UNKNOWN`.
- `out.json.frames.jsonl`: every received JSON message payload, unchanged,
  followed by a newline, in arrival order. Unknown message types and fields are
  retained. The file is flushed after every message.

The runner waits for `Termination` before publishing the transcript atomically.
Success exits 0; authentication, configuration, input, connection, server, and
output errors exit nonzero. An interrupted/failed session can leave a partial
audit log. An existing final transcript is replaced only on success; the audit
log is replaced on each invocation. Both output files use owner-only permissions.
No transcript text or API key is printed to the terminal.

PII redaction is model-based and can miss entities; it cannot provide an absolute
guarantee that every personal detail is removed. Streaming does not redact the
source audio. The runner does not create another audio file.

The Python dependency is already installed in `.venv`; no shell activation is
needed. To recreate the environment:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Verification:

```bash
.venv/bin/python -m unittest -v test_transcribe.py
```

The included `sample-output.json` and `sample-output.json.frames.jsonl` were
generated by a successful live API run using `sample.wav` (five turns, speakers
A and B, approximately 51 seconds of audio).

References: [streaming PII redaction](https://assemblyai.com/docs/streaming/pii-redaction)
and [speaker revisions](https://assemblyai.com/docs/streaming/label-speakers-and-separate-channels).
